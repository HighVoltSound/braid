# braid

**Автопилот качества кода для Claude Code.** Ставишь плагин и работаешь как обычно. Каждый раз, когда Claude за ход меняет код, braid ещё до конца хода:
- запускает реальные проверки проекта;
- отдаёт код на ревью «свежим глазам»;
- пытается опровергнуть каждое замечание;
- исправляет только подтверждённое (для бага сначала пишет падающий тест);
- повторяет, пока не станет чисто.

Тебе остаётся прочитать отчёт.

[English version](README.md)

## Почему так устроено

- **Решают проверки, а не мнение модели.** Тесты, проверка типов, линтер и компилятор Godot — источник истины. «Должно работать» доказательством не считается.
- **Свежие глаза.** Ревьюеры — отдельные агенты. Они не видели, как писался код, поэтому не защищают его.
- **Большинство замечаний ИИ-ревью ложные.** Каждое уходит скептику, который пытается его опровергнуть. Шум не превращается в лишние правки.
- **Ограничения.** Максимум 3 круга и один цикл за ход. Если одно и то же чинится повторно, braid останавливается и пишет «нужен редизайн», а не ходит по кругу.
- **Без лишнего.** Код пишется по лестнице [Ponytail](https://github.com/DietrichGebert/ponytail): не нужно → не делать, переиспользовать, стандартная библиотека, одна строка, и только потом минимум нового кода.

## Установка

```
/plugin marketplace add HighVoltSound/braid
/plugin install braid@braid
```

Нужен Node.js 18+ в PATH: хуки и запуск проверок написаны на Node. После установки начни новую сессию.

## Лучше всего — вместе с Ponytail

[**Ponytail**](https://github.com/DietrichGebert/ponytail) (автор Dietrich Gebert) заставляет Claude писать минимальный код, который решает задачу, причём в каждой сессии и в каждом субагенте. braid — вторая половина: он доказывает, что код работает, и чинит то, что не работает. Вместе получается так: Ponytail держит код коротким, пока тот пишется, а braid проверяет, ревьюит и исправляет его в конце каждого хода.

```
/plugin marketplace add DietrichGebert/ponytail
/plugin install ponytail@ponytail
```

braid работает и без него. Если Ponytail не включён, braid в начале сессии сам даёт Claude короткую версию той же лестницы. Если включён, braid её не дублирует и Ponytail не мешает.

## Как работает

**Автоматически (по умолчанию).** Ничего набирать не нужно. В конце каждого хода, где Claude менял код, хук braid:

1. Гоняет быстрые проверки: типы, линтер, компиляцию, а для Godot — headless-импорт и компиляцию всех скриптов и сцен. Пока они красные, закончить ход Claude не может.
2. Затем один раз за ход просит Claude прогнать цикл ревью braid ровно по файлам, изменённым в этом ходе. Список файлов braid считает сам, с git или без. Твои собственные правки между ходами не считаются.
3. Разрешает пропустить цикл, если правки Claude касаются только комментариев или форматирования, если изменённые файлы — не его правки или если он ждёт твоего ответа. Claude должен коротко это объяснить.

**Вручную**, в любой момент:

| Команда | Что делает |
|---|---|
| `/braid:braid добавь меню паузы` | Делает задачу и прогоняет цикл |
| `/braid:braid` | Цикл по текущим изменениям (`git diff HEAD` и новые файлы) |
| `/braid:braid scripts/player.gd` | Цикл по указанным файлам или папке |
| `/braid:braid audit` | Цикл по всему проекту |

В отчёте будут:
- все проверки с PASS/FAIL по свежему прогону;
- что исправлено, с `файл:строка`;
- какие решения braid принял сам, вместо того чтобы спрашивать;
- что не покрывает ни одна проверка.

**Стоимость.** Один автоматический цикл — это несколько вызовов субагентов. В испытаниях он занимал 2–4 минуты и от $0.25 до $2 на каждый ход, где менялся код (обычные ходы в испытаниях: $0.60–0.72). Если нужны только проверки, поставь `{"gate": "fast"}` в `.claude/braid.json`, а полный цикл запускай сам через `/braid:braid`.

Хук отпускает Claude, если:
- код за этот ход не менялся или совпадает с последним зелёным или проверенным состоянием;
- Claude остановился повторно без правок (например, ошибка была и до него);
- за ход уже было 3 блокировки;
- за ход поменялись сами команды проверок (новые команды без спроса он не запускает).

Отсутствие бинарника Godot никогда не блокирует, а свой лимит времени хук не превышает. Работает и когда сессия открыта в папке с несколькими проектами, например `GODOT_PROJECTS/`: каждый изменённый проект обрабатывается отдельно.

**Доверие:** хук запускает те команды проверок, которые определены в текущем коде: `npm run lint` вместе с его конфигом, записи из `.claude/braid.json`, импорт Godot, при котором выполняются editor-плагины проекта. Это то же доверие, что к хукам из `.claude/settings.json` проекта, поэтому включай его на коде, которому доверяешь. Состояние хранится у каждого пользователя в `~/.cache/braid`.

## Godot

- Только проекты Godot 4 (`config_version=5`). Для Godot 3 пропиши проверки в `.claude/braid.json`.
- Бинарник ищется сам: `GODOT_BIN`, PATH, портативные сборки в `Downloads`, `Desktop`, `Documents`, `Program Files`. Среди найденных побеждает версия из `config/features` проекта, а для C#-проектов берётся .NET-сборка (mono). На Windows берётся `_console.exe`: только он надёжно отдаёт код выхода. Путь можно задать и вручную: `"godot": "C:/путь/Godot.exe"` в `.claude/braid.json`.
- `--import` создаёт файлы `*.gd.uid` рядом со скриптами. Это нормально для Godot 4.4+, их стоит коммитить.
- Папки с файлом `.gdignore` пропускаются, как и в самом Godot.
- Godot завершается с кодом 0 почти при любой ошибке скрипта, поэтому braid читает вывод. Проверку валят `SCRIPT ERROR`, ошибки парсинга и строки `ERROR:`, включая `push_error`. Шум при завершении движка проверку не валит.
- Предупреждения уровня 1 в headless-режиме не видны. Важные из них подними до 2 (ошибка) в `project.godot`, например `gdscript/warnings/untyped_declaration=2`.
- Формат тестов: `tests/<имя>_test.gd`, который `extends SceneTree`. Проверки идут в `_initialize()` после `await process_frame`, чтобы autoload уже существовали. Скрипты проекта подключай через `load()`, к autoload обращайся через `root.get_node("Имя")`, в конце `quit(0)` или `quit(1)`.

## Настройки

| Где | Ключ | Значение |
|---|---|---|
| `.claude/braid.json` | `gate` | `auto` (по умолчанию: быстрые проверки, потом цикл ревью), `fast` (только проверки), `all` (все проверки с тестами, без цикла) или `off`. |
| `.claude/braid.json` | `checks` | Имя → команда. Заменяет автоопределение. |
| `.claude/braid.json` | `godot` | Путь к бинарнику Godot. |
| env | `BRAID_GATE` | Переопределяет `gate` для всех проектов. |
| env | `GODOT_BIN` | Путь к бинарнику Godot. |
| env | `BRAID_TIMEOUT` | Секунд на одну проверку, по умолчанию 600 (в стоп-хуке 120). |

## Испытания

Перед релизом `claude -p "/braid:braid audit"` прогнали на трёх маленьких проектах: JavaScript, Python и Godot 4.7. В них были заложены баги, мёртвый код и ловушки: код, который выглядит неиспользуемым, но вызывается по имени или подключён к сигналу в `.tscn`. Результат оценивали скрытые тесты, которых агент не видел. Финальный прогон:

| Проект | Заложенные баги | Ловушки целы | Мёртвый код удалён | Проверки |
|---|---|---|---|---|
| JavaScript | 2/2 (+3 настоящих бага, найденных самостоятельно) | да | да | зелёные |
| Python | 2/2 | да | оставлен с записанным решением (публичное имя в устанавливаемом пакете) | зелёные |
| Godot 4.7 | 2/2, каждый через падающий тест | да | да | зелёные |

Каждый прогон занял 2–4 минуты. В режиме задачи («добавь команду remove») плагин сделал изменение в одну строку плюс тест, а баг вне задачи не трогал и записал в отчёт. Живая сессия подтвердила, что стоп-хук блокирует сломанную правку GDScript.

Автоматический режим проверили обычными просьбами, без набранного `/braid`:

| Просьба | Что произошло | Стоимость |
|---|---|---|
| «Добавь `cheapest(items)` и команду CLI» (JavaScript) | хук сам запросил цикл по 3 изменённым файлам; 3 ревьюера, исправлять нечего | $0.60 |
| «Добавь `heaviest(items)`» (Godot 4.7) | то же самое, плюс новый тест и зелёные проверки Godot | $0.62 |
| «Поменяй docstring» (Python) | хук запросил, Claude пропустил цикл, потому что правка только в комментарии | $0.25 |

## Ограничения

braid уверен ровно настолько, насколько хороши проверки. На каждый исправленный баг он пишет тест, так что покрытие растёт с каждым запуском. Но того, что ничем не измеряется, он не видит: ощущение от игры, визуал, производительность на реальном устройстве. Это всегда написано в отчёте.

Стоп-хук отличает изменения по времени, а не по автору. Файлы, которые ты правишь, пока Claude работает (или которые пишет другая сессия или автосохранение редактора), попадут в список этого хода. Claude получает указание не трогать правки, которые сделал не он. Две сессии в одном проекте используют общую отметку «проверено».
